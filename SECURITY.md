# Security Policy

## Scope

This repository contains the source code for my personal cybersecurity portfolio and technical blog.

The project is intended to be publicly accessible and contains no user accounts, user-generated content, file uploads, or application functionality that requires storing user data.

## Reporting a Security Issue

If you discover a security vulnerability affecting the website or its supporting infrastructure, please report it privately rather than publicly disclosing the issue.

Please include enough information to reproduce and understand the issue, such as:

* A description of the vulnerability
* The affected component or URL
* Steps to reproduce the issue
* Potential security impact
* Relevant screenshots, logs, or proof-of-concept information where appropriate
* Any suggested mitigation, if known

Please do not include passwords, API keys, authentication tokens, personal data, or other secrets in a report.

## Responsible Testing

Only test the website and its infrastructure in ways that are lawful and proportionate.

Do not attempt to:

* Gain unauthorized access to systems or accounts
* Access, modify, or delete data belonging to other people
* Perform denial-of-service attacks
* Conduct automated scanning at a level that could affect availability
* Attempt social engineering against infrastructure providers or other parties
* Obtain or expose credentials or other sensitive information

The absence of a particular technique from this list does not constitute authorization.

## Repository Security

Please do not commit secrets or sensitive credentials to this repository.

This includes, but is not limited to:

* Passwords
* API keys
* Access tokens
* Private keys
* Cloud credentials
* Deployment credentials
* Session tokens
* Personal data that is not intended for publication

Security-sensitive configuration should use appropriate secret-management mechanisms rather than being stored in source control.

## Content Security

The blog documents penetration testing, security research, CTFs, and other offensive-security topics.

Content is intended for educational and authorized testing purposes.

Security research involving previously unknown vulnerabilities will not be publicly disclosed through this project without first considering responsible disclosure and the potential impact on affected systems and users.

## Supported Versions

The latest version deployed to `alexanderpaulat.de` is the primary supported version of the website.

Older versions are generally not maintained independently.

## Response

Reported security issues will be reviewed and, where appropriate, investigated and remediated.

The response may include:

1. Confirming the reported issue
2. Assessing its impact
3. Applying a mitigation or fix
4. Verifying the fix
5. Deploying the updated version
6. Reviewing whether related components are affected

The specific response process may evolve as the project develops.
